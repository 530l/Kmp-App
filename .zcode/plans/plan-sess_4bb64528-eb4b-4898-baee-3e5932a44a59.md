### UseCase 设计
```kotlin
class GetHomeArticlesUseCase(private val repo: ArticleRepository) {
    operator fun invoke(page: Int): Flow<Result<Page<Article>>> = repo.getHomeArticles(page)
}
```
- 简洁：一个 class，构造注入 repo，`operator fun invoke`
- 解耦：ViewModel 只依赖需要的 UseCase，不直接碰 Repository
- 不抽象：不搞 UseCase 接口 + Impl 那套，直接 class

## 二、导航架构（核心改动）

### Android — 每个 feature 独立管理路由

每个 feature 目录下新建 `navigation/XxxNavigation.kt`，定义自己的 NavKey 和 entryProvider 扩展：

```
androidApp/.../feature/
  home/navigation/HomeNavigation.kt      — HomeKey + EntryProviderScope.homeEntries()
  system/navigation/SystemNavigation.kt   — SystemKey + EntryProviderScope.systemEntries()
  wx/navigation/WxNavigation.kt           — WxKey + EntryProviderScope.wxEntries()
  search/navigation/SearchNavigation.kt   — SearchKey + EntryProviderScope.searchEntries()
  profile/navigation/ProfileNavigation.kt — ProfileKey + LoginKey + EntryProviderScope.profileEntries()
  web/navigation/WebNavigation.kt         — WebKey(url) + EntryProviderScope.webEntries()
```

每个文件形如：
```kotlin
@Serializable data object HomeKey : NavKey

fun EntryProviderScope<NavKey>.homeEntries() {
    entry<HomeKey> { HomeScreen(/* 导航回调 */) }
}
```

顶层 `App.kt` 只做组合：
```kotlin
NavDisplay(
    backStack = currentStack,
    entryProvider = entryProvider {
        homeEntries()
        systemEntries()
        wxEntries()
        searchEntries()
        profileEntries()
        webEntries()
    },
    ...
)
```

每个 Tab 保留独立 backstack（沿用现有模式），feature 间通过回调跳转（`onNavigate: (NavKey) -> Unit`）。

### iOS — 对应拆分
每个 feature 的 View 自带 `NavigationStack` + `navigationDestination`，route 用类型化的值（int id 或结构体），与 Android 的 NavKey 对应。
